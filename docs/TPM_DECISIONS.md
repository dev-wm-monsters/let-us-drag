# TPM decisions (binding)

Answers to open questions raised by the team in phase 1. Owner: TPM.

| ID | Question (raised by) | Decision |
|---|---|---|
| D1 | hamster/struggle not assertable (QA Q-01) | Overlay root exposes `data-uncle-mood="hamster|struggle|none"` (keep `data-hamster`/`data-struggle`). |
| D2 | No hook to drop on the Feed Window (QA Q-25) | Add `dropFilesOnFeed(paths, optionId)` to `LudTestHooks` (Platform: main + E2E-only channel; Frontend: feed renderer handler). |
| D3 | Cancellation UI undefined (QA Q-17) | During chew a small cancel button on the progress ring (`data-testid="cancel-job"`, "Spit it out") + Esc when focused → `cancelJob`. Uncle spits the file back ("Fine, keep it.") and leaves. Engine emits `CANCELLED`, leaves no partial output. Add `cancelActive()` test hook (same code path). Main kills/restarts the worker if a cancelled job is still running after ~5 s. |
| D4 | Overlay lifecycle (QA Q-34) | Created hidden at boot, reused for every gesture. |
| D5 | userData override for E2E (QA Q-35) | `--user-data-dir=<dir>` is honoured (verified). Main must never call `app.setPath('userData')`. |
| D6 | Error code for undecodable input (QA Q-16) | `INPUT_INVALID` wherever detectable; `TOOL_FAILED` only for unexpected tool failures. Messages ≤ 200 chars, no stack traces. |
| D7 | Partial failure in `each` batches (QA Q-13) | All-or-nothing (no outputs committed if any input fails); the message names the failing file. |
| D8 | Unwritable output folder (QA Q-15) | Error `OUTPUT_NOT_WRITABLE`, no fallback location in v0.1. |
| D9 | `arm()` alone; `dropFiles(png, null)`; blocked + option | `arm()` keeps `data-uncle-state="hidden"` (sensor only). `dropFiles(known, null)` → `feedMe` with held files. Blocked inputs → `refuse` and no job, even if dropped on an option. |
| D10 | Remove-BG model source/licence (Engine U6) | Do NOT mirror the weights in our releases (licence of the pretrained weights is not stated upstream). The app downloads them on first use from the upstream rembg release, SHA-256 pinned (`60920e99…`), with a clear one-time-download stage message. Product owner decides about mirroring before public launch. |
| D11 | ffmpeg darwin-arm64 build is nonfree (Security F-01) | Replace it with a GPL (not nonfree) static build for darwin-arm64, resolved and verified in CI (licence check `-L`/`-buildconf` must not contain nonfree; required encoders present; SHA-256 pinned). Other platforms keep ffmpeg-static b6.1.1 with SHA-256 enforced. CI fails if any shipped ffmpeg reports nonfree. |
| D12 | `TEST_DROP_CHANNEL` / LUD_E2E in production (QA Q-31) | Test hooks are installed only when `LUD_E2E=1` AND `!app.isPackaged`. E2E runs against the unpackaged build. |
| D13 | Tray/icon resources in packaged builds (Platform) | electron-builder ships `resources/tray` → `<resources>/tray` and `resources/icon.png` → `<resources>/icon.png` (TPM). |
| D14 | Package size | TPM excludes unused platform binaries (onnxruntime other OS/arch, musl variants, @napi-rs/canvas which cannot run inside Electron, onnxruntime-web except where needed). |
| D15 | Explicit confirm before the 179 MB model download (Security SEC-120, Engine) | No modal confirm inside the drag overlay in v0.1 (it would interrupt the gesture). Instead: the Remove BG bubble hint says "First use downloads a 179 MB AI model (once)", the chew stage text says so while downloading, and cancel works during the download. Accepted deviation, recorded in docs/security/REVIEW.md. |
| D16 | SEC-36 click-through sensor (Platform) | WAIVED: the sensor must be an OS drop target (PLAN §3.5), which a click-through window is not. Mitigation: the sensor only exists while the trigger key is held during a mouse drag, is near-invisible, and hides on mouse-up, lock-screen and suspend. |
| D17 | F-17 MD/DOCX → HTML output | Sanitize the HTML output (same sanitizer as for PDF) and add the no-network/no-script CSP meta. Users get a safe, self-contained HTML file. |
| D18 | F-16 env overrides in packaged builds | When packaged, the engine worker is forked with an environment that has every `LUD_*` key removed (no ffmpeg/model overrides in production). |
| D19 | Esc during chew (QA3-05) | No global Esc shortcut (it would steal Esc from every app during long jobs). Cancel while chewing = the "Spit it out" button, which must be clickable without focus. Esc stays available in interactive states (feedMe). |
| D20 | Overlay blocks clicks during long jobs / steals focus (QA3-06, QA3-07) | Outside the drag gesture the overlay is click-through (`setIgnoreMouseEvents(true, {forward: true})`) except while the pointer is over an interactive element (cancel button, output/error card, option bubbles in feedMe); the renderer toggles this via IPC. It never takes keyboard focus except in feedMe. During arm/sensor/engaged drag it stays a normal drop target (D16). |
| D21 | New gesture while a result card is shown (QA3-11) | A new trigger arm dismisses the card immediately and starts the new gesture. |
| D22 | Network/debug surface in packaged builds (Security F-23, F-24) | Packaged builds refuse `--remote-debugging-port/-pipe` (quit at startup) and disable the spell checker so no dictionary is downloaded: no network request at launch. |
| D23 | Over-long output names (QA3-08) | Shorten the output stem so the final name fits 255 bytes (UTF-8, all OSes) and the full path limits; never fail for name length alone. |
| D24 | Remove-BG reliability (QA3-01) | One fresh `InferenceSession` per job (released afterwards), on every backend. Correctness over the ~1 s session start cost. |
| D26 | Paid licensing with Dodo Payments (product owner brief, 2026-11) | **Hard paywall, no trial: $9.50 one-time, 2 computers.** (1) **Main enforces it**: `startJob` returns `{ started: false, reason: 'LICENCE_REQUIRED' }` and starts nothing without an active licence (so no conversion and no Remove BG model download); renderers get only a `LicenceView` (status, masked key, dates) over `getLicence` / `onLicenceChanged`; `activateLicence` / `deactivateLicence` are Settings-only; links are an enum (`openLicenceLink`) opened with `shell.openExternal`, never an in-app web view. Without a licence the Uncle still appears, but shows one "Unlock for $9.50" bubble with **Buy $9.50** / **I have a key** (state `locked`); × / Esc close him; the Feed Window rests on it; the tray adds "Buy a licence…" / "Activate…". (2) **Dodo API**: only the public `POST /licenses/activate {license_key, name}`, `/validate {license_key, license_key_instance_id?}`, `/deactivate {license_key, license_key_instance_id}`; no API key anywhere. Hosts `https://test.dodopayments.com` / `https://live.dodopayments.com`, checkout `https://[test.]checkout.dodopayments.com/buy/<product>?quantity=1&redirect_url=…/thanks/`, chosen at build time by `DODO_ENV` (test\|live) + `DODO_PRODUCT_ID` (electron-vite `define`; CI: repo variables, default test; `DODO_ENV=live` with the test product fails the build). Error mapping: 404 not found, 403 not active, 422 limit, network → friendly texts (src/shared/licence.ts). A product ID in the answer must match. (3) **Storage**: `licence.dat` encrypted with `safeStorage`; no encryption available → `licence.json` mode 0600, logged; unreadable → unlicensed, never a crash. Anonymous device ID: random UUID v4 in `install-id`. Device label `<OS> · <CPU> · <6 hex of the ID>`, never the hostname. A licence stored for the other environment is ignored. (4) **Re-check**: validate with the instance at most once per 24 h, after a random 45–165 s delay at start-up and after wake (powerMonitor `resume`) when due; silent. Locks **only** on a definite answer (2xx `valid:false`, 403, 404), confirmed by a second check 60 s later; then the key alone decides `disabled` vs `reactivate` ("activate again", key still valid). Offline / DNS / TLS / timeout (15 s) / captive portal / 5xx / 429 / unexpected → keep state, retry after 1, 3, 6, 12 h. No offline time limit. A disabled key that becomes valid again unlocks. (5) **Deactivate**: confirm dialog; online → seat freed, back to the paywall; offline / 5xx → keep the licence and say so; 403/404 (already gone) → cleared. (6) **Network exception to D22**: the licence calls are the only new traffic, from main through an in-memory `lud-licence` session restricted to the Dodo origin (system proxy applies; generic `User-Agent`, no `Accept-Language`, no cookies). Nothing is sent at launch: the re-check is delayed and only runs when a licence exists and is due. (7) **Test bypass rules** (D12/D18): `LUD_E2E_LICENSE=active` (start licensed, in memory only) and `LUD_E2E_DODO_URL=<loopback mock>` are honoured only when `LUD_E2E=1` AND `!app.isPackaged`; without the mock URL E2E points at an unroutable address; `shell.openExternal` is replaced by a recorder (`__ludTest.openedUrls()`); `__ludTest.licenceRecheckNow()` runs the timer's code path. The E2E fixture defaults to licensed so the conversion specs keep converting. The "Reset licence (development)" tray item exists only unpackaged. Casual-sharing protection only (THREAT_MODEL §5.14). |
| D27 | Remove-BG cut-out quality without changing the model (Engine, 2026-11) | Same model, same rembg-identical pre-processing (re-checked against rembg 2.0.86 `DisSession`: 1024² LANCZOS, ÷max, mean 0.5, std 1.0, min-max output), same D24 sessions and backends. New post-processing in `src/engine/tools/mask-refine.ts` (pure, unit-tested), run at a work size of ≤ 1024 px long side with only the final steps at full size: (1) drop disconnected islands (components of the raw mask > 0.05 with < 2 % of the largest one's mass; several similar-sized subjects all stay); (2) upscale the mask (lanczos3), then alpha levels 0.15 → 0, 0.85 → 1, linear between (kills faint ghosting/smears and makes the subject truly opaque: the raw output tops out at 254); (3) colour decontamination of semi-transparent pixels by blur-fusion foreground estimation (Forte & Pitié 2021, radii 90/6 per 1024 px). Measured on 8 photos (tiger, girl with raised arms, rocket towers, cat close-up, astronaut, coffee, Grace Hopper, motorcycle): pixels with alpha 1–254 fell from 19–88 % to 0.8–13 %; alpha 25–230 from 1.1–22.8 % to 0.6–9.6 % (cat close-up 22.8 → 9.6 %); added time ~0.05–0.3 s per image at ≤ 1 MP and ~0.3 s at 12 MP (4000×3000, 4 cores: cut-out stage incl. PNG ~1.1–1.2 s vs ~0.85–0.9 s before), roughly +100 MB peak at 12 MP. Visibly better or equal on every test image (no blue background rims on the girl's cap/arm or Hopper's hat, crisper edges, much less smear under the tiger, rocket lattice in its real colour); not fixed: the cat close-up's mid-alpha ghost (the model's own uncertainty) stays partly visible. Tried and rejected: colour guided filter (washed out thin lattice beams, no gain on hair) and hole filling (filled lattice gaps and wheel spokes). Known trade-offs: objects the model only half-detected (mostly ≤ 15 % alpha) fade out instead of showing as ghosts; light flares the model wrongly included take the colour of the nearby subject. |
| D29 | Update notices without auto-update (product owner brief, 2026-11; no Apple Developer ID yet) | **Notices only, same on every OS, no auto-install.** (1) Main reads a small JSON manifest (`UPDATE_MANIFEST_URL`, build setting, default `https://letsdrag.wakeupmonster.com/update.json`; format in `docs/update.json.example`, zod-validated, unknown fields ignored, semver incl. pre-releases). (2) **Soft** (this < `latest`): tray item, Settings banner (**Download** / **Later**), once per version an Uncle note "I learned new tricks! Update in Settings." that never blocks a drop or a job; **Later** hides banner + note for that version (`userData/update-state.json`, not settings). (3) **Force** (this < `minimum`): main refuses `startJob` with `UPDATE_REQUIRED` (checked before `LICENCE_REQUIRED`; no job, no Remove BG download); overlay / Feed Window show the locked state with "Please update me" + **Download** (× / Esc close him); Settings shows a red banner. The last valid manifest is cached, so a forced state survives offline restarts; never fetched → not blocked; a manifest that lowers `minimum` unblocks. (4) **Download** opens, in the default browser, the per-OS link from the manifest, accepted only as https on `letsdrag.wakeupmonster.com`; anything else → the download page. The renderer never passes a URL. (5) **Network**: one plain GET, from main, through the in-memory session `lud-update` restricted to the manifest's origin, generic `User-Agent: LetsDrag/<version>`, no cookies, no query, no IDs, 10 s timeout, no redirects. First check 20–60 s after start-up (**second documented exception to D22**: never during start-up itself), then every 6 h, and after waking from sleep when more than 6 h passed. Every failure is silent and keeps the previous state; a failed check never blocks. (6) Team builds (`LUD_LICENSING=off`) behave the same. (7) E2E: `LUD_E2E_UPDATE_URL` (loopback only; `LUD_E2E=1` and unpackaged only, D12/D18), hooks `update()`, `updateCheckNow()`, `updateResume()`; the default fixture has no update state. Trust root: the website host (threat model §5.15). Details: `src/main/README.md` "Updates". |

**D26 addendum (2026-11-03, checked against Dodo's docs and official skills):** a successful refund of the one-time payment disables the licence key automatically (`refund.succeeded` → key disabled, grant `revocation_reason: refund`; docs.dodopayments.com/features/license-keys), so no manual step and no webhook are needed; the app sees it at its next re-check. Dodo's sample code fails closed after a 30-day offline grace period; we deliberately never lock for being offline, because the website and Terms promise it (a refunded user who stays offline keeps access until their next online check: accepted at $9.50). Dodo's customer portal lets buyers retrieve lost keys but not remove activations, so a lost or broken computer's seat is freed by support in the dashboard. For go-live, Dodo's checklist says to create the live product fresh in live mode rather than relying on a copy, with the same licence settings and tax category.
